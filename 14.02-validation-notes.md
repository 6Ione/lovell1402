# Afterglow 14.02 validation notes

Scope: static validation against the supplied `kernel_1402.bin`; no console execution or runtime exploit test was performed.

## Confirmed against the supplied kernel image

- Kernel image size: 28,468,720 bytes.
- SHA-256: `a1522676dabb9cb51a1f94ebced0e725b1d605202a87f6c07aad2625c169a704`.
- Executable PT_LOAD: VA `0xffffffff96810000`, file offset `0`, file/memory size `0xCFE9A0`.
- Writable PT_LOAD: VA `0xffffffff97d30000`, file offset `0xD20000`, file size `0x606690`, memory size `0x1314AF0`.
- All 15 byte signatures in Afterglow's `PATCHES` table match the supplied kernel at their current RVAs (15/15).
- `4E 95 C3` occurs once in the supplied image, at RVA `0xA81478`; the current 0x1000-byte scan window around the old seed `0xA80F68` includes it.
- The supplied research notes and kernel disassembly support PRISON0 at RVA `0x01A5C110` as a direct structure address. The previous source treated RVA `0x111FA18` as a pointer slot and dereferenced it.

## Changes in this working copy

- Corrected the 14.02 PRISON0 address and removed the erroneous pointer dereference.
- Centralized the 14.02 text/data segment sizes and updated the debug-menu scan and optional dump sizes.
- Corrected stale comments that described the old PRISON0 pointer-slot behavior.

## Still unverified / required evidence

- Browser-side WebKit offsets in `PS4["14.02"]` are inherited from the 14.00/13.52 row and explicitly described as assumed. They are not independently verified by the supplied kernel dump.
- `libSceLibcInternal` gadget offsets/signatures and spare executable tail must be checked against the exact 14.02 module build.
- `libkernel_sys` syscall-stub discovery and the browser entry primitive need validation against the exact 14.02 runtime modules.
- Kernel anchor `0xE6C30` is retained as the current 14.02 reference, not promoted to a proven runtime anchor by this static pass.
- No exploit execution, privilege transition, or payload launch has been demonstrated.
